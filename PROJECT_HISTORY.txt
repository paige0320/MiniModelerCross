MiniModeler / MiniModelerCross project history
Generated: 2026-05-11

Goal
----
The goal started as learning how to write shader/rendering code and show a 3D cube. Because the machine is macOS on Apple Silicon, the initial Windows/Visual Studio + HLSL + Direct3D path was replaced with macOS-friendly Metal. Later, the goal expanded into a small modeling-program prototype that can also run on Windows and use Dear ImGui for editor UI.

Phase 1: Direction choice
-------------------------
1. Explained that HLSL + Direct3D is a Windows path and is not the best fit for macOS M1.
2. Recommended Xcode + Metal + Metal Shading Language for native macOS shader/rendering learning.
3. Explained that a small modeling program is realistic if built in stages: viewport, cube, camera, scene objects, transforms, selection, then editing tools.

Phase 3: Cross-platform direction
---------------------------------
Explained that Swift + AppKit + Metal is macOS-only. For Windows compatibility and Dear ImGui integration, the project needed a C++ cross-platform stack.

Chosen stack:
- C++17
- CMake
- GLFW
- OpenGL 2
- Dear ImGui

Reasoning:
- Dear ImGui is C++.
- GLFW gives a cross-platform window/input layer.
- OpenGL 2 avoids extra OpenGL loader setup for the first cross-platform prototype.
- CMake lets Visual Studio on Windows and Xcode/command line on macOS open/build the same project.

Current limitations
-------------------
- The renderer still uses OpenGL 2 fixed-function mode for simplicity.
- Texture support is currently procedural checker texture only, not image-file loading.
- Object-mode selection uses local bounding boxes.
- Edit-mode face selection uses ray/triangle picking on the selected object's mesh.
- Edit mode is a first version and does not yet have Blender-style topology tools.
- There is no transform gizmo yet.
- There is no undo/redo yet.
- There is no OBJ or glTF import/export yet.

Phase 7: First Edit Mode
------------------------
Added a first usable mesh edit mode to MiniModelerCross.

Implemented:
- Each SceneObject now owns its own Mesh copy instead of only referencing a shared primitive mesh.
- Edit Mode toggle in the Dear ImGui panel.
- Keyboard shortcut:
  - E: toggle Edit Mode
- Selection modes:
  - Vertex
  - Edge
  - Face
- Left click behavior:
  - Object Mode: selects whole objects.
  - Edit Mode: selects the active mesh element type on the selected object.
- Vertex editing:
  - selected vertex is highlighted.
  - selected vertex local position can be edited with ImGui DragFloat3.
- Edge editing:
  - selected edge is highlighted.
  - both edge endpoint local positions can be edited.
- Face editing:
  - selected triangle face is highlighted.
  - Push + / Push - moves the face along its face normal.
- Mesh recalculation:
  - normals are recalculated after edits.
  - local bounds are recalculated after edits.
- JSON persistence:
  - saved scene JSON now includes edited vertex positions.
  - loading restores vertex positions when the saved vertex count matches the primitive mesh.

Important limitation:
- The current primitives use per-face or generated vertices, not fully welded topology. This means editing a cube corner may move only the selected face's copy of that corner instead of every adjacent face. The next topology milestone is vertex welding / shared vertex topology.
